# schema-inference\n\nInfer deterministic JSON Schema (Draft 2020-12) from JSON records or CSV rows. Merges every record into one schema with explicit rules for nullability, types, and required keys.\n\n## Problem\n\nTeams receiving JSON exports or CSV files often lack schemas to validate deliveries. Manually authoring them is error-prone, and existing inference tools often use the first record as the sole source of truth or cast identifiers like \"007\" into integers incorrectly. This utility merges all records into a single, deterministic schema.\n\n## Installation\n\n```bash\npip install schema-inference\n```\n\n## Usage\n\n```python\nfrom schema_inference import infer_json\n\nrecords = [{"id": 1, "tag": "test"}, {"id": 2}]\nschema = infer_json(records)\n# Output includes $schema and properties\nprint(schema["required"])  # ['id']\n```\n\n## Public API\n\n- `infer_json(records, *, max_records=100000, max_depth=32, max_properties=1000)`: Infers from an iterable.\n- `infer_csv(rows, *, null_tokens=frozenset({'', 'NA', 'N/A', 'null', 'NULL'}), max_records=100000)`: Infers from CSV rows.\n- `infer_value(value, *, max_depth=32)`: Schema for a single value.\n- `merge_schemas(a, b)`: Merges two schemas.\n- `SchemaInferenceError`: Exception with code `invalid_value`, `too_deep`, `too_many_records`, `too_many_properties`, `invalid_input`.\n\n## Why not genson\n\nGenson does not support explicit CSV typing that preserves identifiers as strings (e.g., \"007\"), lacks precise format detection for RFC 3339, and produces output that varies with key insertion order.\n\n## Security\n\nSee [docs/SECURITY.md](docs/SECURITY.md).
